# V59 — доработки по замечаниям пользователя

Дата: 26.11.2026. Ветка: `arena/4e17b75a-rs`.

Ниже — что именно поменялось, почему это было сломано и что осталось
проверить руками.

---

## 1. Главная страница и «Базы моделирования»

**Было.** Главная (`/`) была отдельной самодельной страницей: логотип и
четыре кнопки. Ни шапки, ни меню, ни темы. «Базы моделирования» начинались
с кнопки «На главную» и тоже не вызывали общий макет.

**Причина.** Обе страницы не вызывали `create_page_layout()` — шапку,
боковое меню и тему рисует именно он.

**Стало.**

* `/` собирается через общий макет и показывает сводку: объекты, базы,
  типы, записи аудит-лога (`RS_HOME_LAYOUT_V59`).
* «Базы моделирования» — тоже общий макет, кнопка «На главную» больше не
  нужна: есть меню (`RS_DATABASES_LAYOUT_V59`).
* Макет научился принимать пояснение под заголовком: `create_page_layout(title, subtitle)`.

Проверено: обе страницы отдаются сервером (200) и содержат шапку,
меню и блок темы.

## 2. Объекты: карточка и атрибуты

**Было.** В карточке объекта — пустой список и кнопка «Добавить атрибут».
В диалоге атрибута «топорный» выпадающий список «Тип значения»: Строка /
Число / Дата / Логическое значение. Пользователь сам придумывает и
название, и тип.

**Стало.** Набор полей зависит от типа объекта
(`rubik_studio/core/object_attributes_v59.py`):

| Тип | Поля |
|---|---|
| Документ | Номер, Дата документа, Статус (выбор), Автор, **Файл документа**, Действует до |
| Клиент | **ФИО** (обязательно), Дата рождения, Телефон, Почта, Тип клиента, Дата договора |
| Организация | ИНН, КПП, Юр. адрес, Сайт, Дата регистрации |
| Сотрудник | ФИО, Должность, Дата приёма, Почта, Телефон |
| Процесс | Владелец, Событие начала/завершения, Частота, Уровень автоматизации |
| Система | Вендор, Версия, Адрес, Ответственный, Дата ввода |
| Регламент | Номер, Дата утверждения, Утвердил, Файл, Редакция |
| Риск | Вероятность, Влияние, Уровень, Меры снижения |
| Требование | Номер, Приоритет, Источник, Принято |

Остальные типы получают общий набор (код, ответственный, источник, дата) —
он осмысленнее пустоты.

Важное:

* под каждым полем — подсказка формата; вид значения подписан в
  всплывающей подсказке, отдельного выпадающего списка больше нет;
* **пустые поля не сохраняются** — карточка не разрастается;
* **обязательные поля проверяются** (у клиента без ФИО сохранение не пройдёт);
* **свои атрибуты старых карточек не теряются**: они показываются отдельным
  блоком «Свои свойства»;
* у полей-файлов видна ссылка «файл прикреплён».

**Про «повторы» в списке объектов.** Проверил все 30 типов: повторов по
названию и по коду нет. В списке 123 / 345 / 678 на скриншоте — разные
типы (Данные, Бизнес-событие, Технический компонент). Похожие по смыслу
пары в справочнике есть (Документ / Регламент / Данные, Услуга /
Бизнес-сервис, Сотрудник / Должность / Роль) — это разные сущности
BPMN/ArchiMate, удалять их нельзя, иначе поедут существующие объекты.
Если хотите, могу переименовать подписи, чтобы разница читалась
(например «Данные (объект)» и «Информационный поток»).

## 3. BPMN

### 3а. Кривые границы привязки стрелок

**Причина.** Событие рисуется кружком 60 px, но его блок в разметке —
180 × 70. Расчёт точек присоединения брал габариты блока, поэтому линия
начиналась в пустоте в 60 px от кружка. Плюс форма `data-rs-shape`
ставилась только трём старым кодам событий — новые (таймер, ошибка,
граничное) считались прямоугольниками.

**Стало** (`RS_DIAGRAM_ANCHOR_V59`):

* точки берутся по **видимой фигуре**: круг — радиус 29, ромб — 30;
* форма задаётся по типу символа из единого каталога (`EVENT_KINDS`,
  `GATEWAY_KINDS` в `bpmn_shapes_v55.py`) — новый символ автоматически
  получает правильную форму.

### 3б. Потоки читаются плохо

**Стало** (`RS_FLOW_VISIBLE_V59`):

* потоки V29 рисуются толщиной 2.6 вместо 2;
* у потока **сообщения** — открытая стрелка, у **управления** — сплошная;
* вид потока пишется и в скрытую `<line>`, и в видимый маршрут `<path>`:
  раньше правка доставалась только скрытому элементу, и на экране ничего
  не менялось.

Ограничение: как это выглядит на конкретной диаграмме с граничным
сообщением — надо смотреть глазами, я проверял разметку и координаты,
а не картинку в браузере.

### 3в. Каталог «Начальное / Промежуточное / Граничное / Конечное»

**Причина (найдена).** Клик по вкладке менял карточки, но **не
перекрашивал саму кнопку** — выбранная вкладка оставалась серой, и
казалось, что ничего не произошло. Плюс четыре кнопки стояли в один ряд
в панели шириной 13 %: «Промежуточное» и «Граничное» вылезали за край.

**Стало.** Вкладки стоят сеткой 2 × 2 и подсвечиваются акцентом при
выборе (`RS_EVENT_TABS_V59`, `RS_EVENT_TABS_ACTIVE_V59`). Переключение
проверено тестом в симуляторе: start → boundary → end показывают свои
подтипы.

### 3г. Сворачиваемый каталог символов

`rubik_studio/ui/bpmn_palette_v59.py`, функция `collapse_group()`:
каждая группа — строка-заголовок со счётчиком и стрелкой. Свёрнутая
группа не создаёт карточки вообще, поэтому панель открывается быстро.
По умолчанию раскрыты «Задачи» и «Шлюзы» и палитра событий.

### 3д. Перетаскивание символа на поле

Карточку символа можно **тащить мышью (или пальцем) прямо на диаграмму**:
полупрозрачная копия едет за курсором, при отпускании символ встаёт точно
под курсор с учётом панорамирования и масштаба. Кнопка «+» осталась.

> Требуется ручная проверка: перетаскивание работает в браузере, в
> симуляторе я проверил только наличие обработчиков и приём события.

## 4. Бесконечный рабочий стол

**Было.** Лист 20000 × 20000 с жёсткой рамкой, `overflow:hidden`:
за краем листа элементы обрезались, а сама рамка была вложена в поток
страницы.

**Стало** (`RS_INFINITE_CANVAS_V59`):

* панель символов — неподвижный брусок слева, лист под ней двигается
  панорамированием (пробел + перетаскивание) и масштабируется колесом;
* рамка полотна занимает всю доступную высоту экрана (`calc(100vh - …)`,
  минимум 420 px), а не «сколько получилось»;
* лист **растёт под содержимое**: `canvas_extent()` добавляет 2000 px
  запаса за крайним элементом, лимит координат — 1 000 000;
* сетка нарисована на листе и едет вместе с ним — движение читается;
* обрезки по краю больше нет (`overflow:visible`).
