# Как передать большой проект Rubik Studio

Если архив проекта весит сотни мегабайт — почти всё это служебные файлы,
а не исходники. Ниже два проверенных пути.

---

## Вариант 1 (рекомендуемый): git push напрямую

Не нужен ни zip, ни веб-загрузка — работает с любым объёмом, докачивается при
обрыве и сохраняет историю. Из папки проекта:

```bash
git init                      # если git ещё не инициализирован
git add .
git commit -m "Мой проект Rubik Studio"
git remote add origin https://github.com/SUMRATOR/rubik-studio-test.git
git branch -M main
git push -u origin main --force
```

Git сам не отправит лишнее, если есть `.gitignore` (он лежит в этом репозитории —
скопируй его в корень проекта). Если папка уже под git — достаточно двух строк:

```bash
git remote add origin https://github.com/SUMRATOR/rubik-studio-test.git
git push -u origin main
```

После этого пришли мне ссылку `https://github.com/SUMRATOR/rubik-studio-test` —
я склонирую сам, ничего загружать в чат не нужно.

> ⚠️ `--force`, если репозиторий нужно перезаписать полностью. История старой
> версии при этом пропадёт — если она нужна, сделай `git push origin main`
> без `--force` и разберись с конфликтами, либо скажи мне, я помогу.

## Вариант 2: чистый архив с разбивкой

### Шаг 1. Собери чистый архив

Скачай из этого репозитория `tools/make_archive.py` и запусти из любой папки:

```bash
python make_archive.py "C:\путь\к\папке\проекта"
```

Скрипт покажет, что занимало место, и создаст `название-src-<дата>.zip`.
Исключаются: `.venv`, `__pycache__`, `node_modules`, `data`, `uploads`, `build`,
`dist`, `*.db`, `*.log`, `*.pyc`, `*.zip`, файлы больше 20 МБ.

### Шаг 2. Разбей, если получилось больше 24 МБ

```bash
python make_archive.py "C:\путь\к\проекту" --split 24
```

Получишь `…zip.001`, `…zip.002`, … — каждый меньше лимита GitHub (25 МБ).

### Шаг 3. Загрузи на GitHub

Репозиторий → **Add file** → **Upload files** → перетащи **все** части разом →
**Commit changes**.

> GitHub не даёт загрузить файл больше 25 МБ через веб-интерфейс, поэтому
> и нужна разбивка. Не переименовывай части — порядок `.001`, `.002`
> важен для сборки.

### Шаг 4. Пришли ссылку

`https://github.com/SUMRATOR/<репозиторий>/blob/main/<файл>.zip.001` — дальше я
соберу части сам.

### Проверка у себя (по желанию)

```bash
python assemble_parts.py "название-src-<дата>.zip" --extract
```

Скрипт соберёт части, проверит целостность zip и распакует.

## Что точно не сработает

| Канал | Почему |
|---|---|
| Яндекс.Диск, Google Drive, Dropbox, Mail.ru Cloud | из моей песочницы эти домены недоступны |
| `raw.githubusercontent.com`, ассеты GitHub Releases | редирект на заблокированный домен |
| Вложение 500 МБ в чат | слишком большой объём для загрузки |
| Один файл 500 МБ через веб-интерфейс GitHub | лимит 25 МБ (жёсткий предел 100 МБ) |

Работают: `github.com`, `api.github.com` и git-операции (`clone`/`fetch`/`push`).
